# Akasha 记忆图：三屏交互原型

第二轮原型用于评审大量记忆中的查找、局部探索和来源回溯。
沿用 Roxy Mobile 主题；所有对话、节点、时间、版本和权重均为合成样例。
功能范围依据：[首版功能约定](../../../docs/design/akasha-mobile-memory-graph.md)。

| 屏幕 | 第二轮交互 |
|---|---|
| 图概览 | 默认折叠关联组并显示成员数；每批展开 8 段记忆；共享成员保留同一身份及多个组的连线；搜索完整示例集合，每页 12 条 |
| 局部关联 | 围绕一个节点，每批显示 10 个邻居；明确当前页与总范围；筛选关系类型、聚焦选中连线、继续以所选节点为中心探索 |
| 节点详情 | 查看并复制原始对话；共享记忆显示所属组；关联列表每页 10 条；支持定位回图和逐层返回 |

默认进入 160 段记忆的密集场景。右侧可切换普通、大图、空图与读取失败，或进入三个任务的起点。
“模拟版本更新”提示刷新后继续查询；“重新体验”回到密集图的折叠概览。
视图显示范围和搜索页码保存在浏览器内，进入详情再返回后可以续看。

## 三个任务的评审方法

| 任务 | 操作 | 可观察的完成条件 |
|---|---|---|
| 找到未展开的记忆 | 从密集概览搜索“北极星计划”，进入局部图，再查看详情 | 找到 `dense-143` 的完整原文；该节点不在初始概览中 |
| 识别共享成员 | 查看 `dense-12` 的局部关系和详情，分别进入两个所属组 | 两组都指向同一段记忆；界面说明组数不能直接当作去重记忆数 |
| 探索高连接组 | 打开 `dh0`，翻到第二批，选择成员、进入详情、再返回 | 当前页恢复，仍能继续翻页访问剩余成员，原始关联数量不变 |

另用 1,000 段样例搜索“纸飞机项目”，应找到初始未展开的 `large-913`。
浏览器自动化验证任务路径是否可达；人的完成时间、理解程度和主观拥挤感仍需用户实际试用记录。

## 完整样例与显示范围

下表为 V12 的完整合成集合。刷新后的 V13 增加一段记忆并保留已有身份。

| 场景 | 回合 / 关联组 | 关联条数 | 共享回合数 | 最大组的成员数 |
|---|---:|---:|---:|---:|
| 普通 | 13 / 3 | 23 | 1 | 5 |
| 密集 | 160 / 4 | 404 | 81 | 114 |
| 大图 | 1,000 / 8 | 2,608 | 568 | 654 |
| 空图 | 0 / 0 | 0 | 0 | 0 |

组内成员数允许重叠，页面总记忆数按身份去重。图仅绘制当前投影，分页范围始终明确。
`src/data.js` 保存完整合成集合，`src/projection.js` 生成聚合、分批一跳和全范围搜索结果。
当前 10 组场景/版本的 8,448 份图投影检查中，最多为 16 个节点、18 条边、13,266 字节 JSON。
它们低于初始 100 节点 / 200 边 / 128 KiB 的预算；未来真实传输还需计算 envelope。

大图完整 fixture 约 736 KiB，保存在原型进程中用于模拟完整查询目录，并非一份图查询响应。
真实接入应由插件端检索和返回有界投影，不能照搬把所有真实来源下载到手机的方式。
当前样例最多 8 个关联组；更多组的概览范围、选择规则与性能需要后续真实数据探针验证。

## 状态与写入边界

- 第二轮使用 localStorage 键 `roxy.akasha.graph-prototype.v2`，保存页面、场景、节点身份、版本、搜索及概览/局部页码。
- 第一轮对照继续使用 `.v1`，互不覆盖。完整返回历史和拖动布局不持久化。
- 折叠、筛选、聚焦和翻页只修改浏览状态，不修改 fixture、权重或来源。
- “复制示例记忆”仅在主动点击时写入剪贴板。
- 刷新、错误和版本变化由本地状态模拟，页面没有真实数据库、模型或插件 API 请求。

本轮为设计原型迭代，生产语义不变。写集合为此原型目录、完整设计 manifest 和功能约定的原型说明。
当前任务为唯一 repository writer，浏览器复核与静态服务检查仅只读源码。
其他效果限于本地构建、回环地址静态服务、临时浏览器 profile、隔离报告与本地提交。
生产源码、Gate 合同、真实运行目录、手机安装与远端仓库均不在写入范围内。
