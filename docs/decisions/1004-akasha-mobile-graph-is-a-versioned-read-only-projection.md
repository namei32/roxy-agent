# 1004 · Akasha 手机记忆图使用版本化只读投影

- 状态：accepted（用户在三屏原型后明确要求完整实现）
- 日期：2026-09-05
- supersedes：[0006](0006-akasha-v2-is-the-canonical-explicit-memory-engine.md) 第 7 项及验收中的手机端不展示图限制；其他约定继续有效。
- 关联：MOB-001、MOB-006、PLG-011、STA-001～STA-003、MEM-009～MEM-010、TST-002。

## 背景

用户需要从手机插件列表找到记忆，查看关联与原文。既有 Inspector 解释单次检索，
不提供当前拓扑。三屏原型已确定聚合概览、分批一跳探索、共享成员和来源详情。

## 决定

1. 在现有 `akasha` 插件导航中增加记忆图，保留 Inspector 和回复召回卡片。
   查询、展示和选择规则由 Akasha 插件拥有；复用既有 HTTPS 查询数据面与宿主 lease。
2. 只读取最近有效发布的 SQLite 图及其来源，不执行检索、embedding、反馈或重建。
   浏览不得尝试修改 SessionDB、sidecar、pending retrieval ticket 或配置。
3. 图响应使用独立 schema 和发布 revision。回合身份来自稳定 turn ID；Hub 身份
   来自创建它的来源回合，不能使用会随容量变化的数组位置。过期请求要求刷新。
4. 概览关联组也分页；搜索覆盖全部已发布回合。一跳查询由领域端选择邻居分页，
   保证边端点齐全，并返回精确总数、当前范围和下一页。每份响应不超过 100 节点、
   200 条边、128 KiB UTF-8 JSON。客户端完整展示返回集合。
5. Hub 使用中性关联组名称；共享成员仍是同一回合。权重称为关联强度，时间关系
   带方向；当前关系不表示事实可信度、因果关系或历史检索的实际传播路径。
6. 长来源按 Unicode code point 分段，只读页可完整浏览。来源失效、发布竞争、
   未启用、空图、节点不存在和请求故障具有不同状态；旧结果不能覆盖新视图。

## 理由与影响

插件可以读取权威关系，客户端不能从旧 Inspector DTO 推测拓扑，因此无需新增 Core
或 Android 协议。只读投影不产生数据库迁移、独立图缓存或第三份事实源。
图的分页定义新增浏览查询的范围，完全不改变 0009 的既有 recall lane 完整性。

当前宿主镜像的历史漂移先在独立 canonical checkout 对齐并提交，保持宿主原字节，
再开发本功能并更新固定镜像身份。本地提交和构建不代表远端发布或已部署到手机。

## 验收

- 确定来源的真实 SQLite 样例验证节点、方向、共享身份、完整分页与全范围搜索。
- 只读 authorizer、写入故障注入和完整持久快照验证零写入尝试。
- 发布更换、容量扩展、来源撤销、缺失侧库、长 Unicode 正文与迟到请求有明确结果。
- 原召回集合和顺序保持；手机尺寸验证真实查询驱动的三屏与 Inspector 切换。
- 源码镜像、构建、定向检查和完整公开 Gate 分层记录；设备与部署证据另列。
